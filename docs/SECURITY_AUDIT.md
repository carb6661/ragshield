# 安全审计说明

本文记录 RAGShield 开源前的默认安全边界。它是项目级自查，不替代独立渗透测试、
供应链审计或合规认证。

## 2026-08-13 审计结果

- Bandit 扫描 970 行 Python 代码：中危、高危问题均为 0；
- `pip-audit backend/` 隔离解析项目声明依赖：未发现已知漏洞；
- `npm audit --audit-level=low`：未发现漏洞；
- Ruff、25 项 Pytest 与前端生产构建通过；
- 当前工作树未发现私钥、GitHub/Gitee Token、真实密码或本机绝对路径；
- Git 提交使用 GitHub noreply 邮箱，仓库尚未配置远端。

Codex 共用 Python 运行时中的 `pypdf 6.10.0` 存在公开漏洞，但 RAGShield 的
`pyproject.toml` 不依赖该包，项目源码也不导入它。隔离项目审计结果不受此影响。

## 默认本机影响

- Docker 端口仅绑定 `127.0.0.1`，不向局域网公开；
- Compose 不使用特权模式、宿主机目录挂载或自动重启策略；
- 后端容器使用非 root 用户；
- 扫描历史只写入 SQLite 文件或 Docker 命名卷；
- 前端不加载第三方字体、统计脚本或远程图片；
- 默认不访问模型服务或其他 HTTP 目标；
- 示例服务只监听 `127.0.0.1`，示例数据不包含真实个人信息或凭据。

## 账号影响

运行项目不会读取或修改 GitHub、Gitee、Git、SSH、浏览器或云平台账号。仓库没有
自动发布逻辑；只有用户主动配置 Git 远端并执行 `git push` 才会产生账号写入。

推送到 GitHub 后，现有 CI 工作流会在 `main` 分支推送和 Pull Request 时运行，
可能消耗账号的 GitHub Actions 免费额度。工作流权限仅为 `contents: read`，不会
发布包、创建 Release、修改 Issue 或推送代码。

## 网络目标安全边界

授权 HTTP 适配器默认关闭。启用时要求精确主机白名单，并默认拒绝非 HTTPS、URL
凭据、重定向、环境代理和非公网解析结果，同时限制超时与响应大小。Bearer Token
不写入数据库，但通过 CLI 参数传递时可能被本机进程列表或命令历史看到，应优先
使用短期测试凭据和隔离环境。

DNS 检查和实际连接之间仍存在理论上的 DNS rebinding 时间窗口，因此不要把
RAGShield 部署成无身份认证的公共扫描服务，也不要为不受信任用户配置宽泛白名单。

## 数据与隐私

`.env`、SQLite、构建目录、虚拟环境、Node 依赖和 Python egg-info 均被 Git 忽略。
报告可能包含目标响应片段；接入真实测试环境前，应确认响应中不包含不应进入扫描
历史或 CI Artifact 的敏感数据。

## 已知非目标

- 不提供恶意软件、持久化、漏洞利用或任意互联网扫描能力；
- 不声称覆盖所有提示词变体或自适应攻击；
- 通过控制不等同于安全认证；
- 默认 SQLite 适合本地和演示，不是多租户生产数据库。
