# Contributing to RAGShield

Thank you for helping improve defensive RAG security.

1. Open an issue describing the control, defect, or documentation change.
2. Fork the repository and create a focused branch.
3. Add regression tests for behavior changes.
4. Run the backend test suite and frontend build.
5. Submit a pull request with a concise threat model and safe reproduction.

New controls should contain a stable identifier, severity, deterministic test
case, safe and unsafe markers, remediation, and an OWASP or MITRE mapping. Test
payloads must be inert and must not contain real secrets or destructive actions.

By participating, you agree to keep discussions respectful and focused on safe,
authorized security research.
